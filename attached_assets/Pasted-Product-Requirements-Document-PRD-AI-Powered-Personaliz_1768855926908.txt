Product Requirements Document (PRD)
AI-Powered Personalized Website with Visual Editor
Executive Summary
This project delivers an AI-powered, single-page website platform that dynamically personalizes content for each visitor. The system identifies users through both anonymous tracking and authenticated login, retrieves customer profile data from BigQuery, and adapts content in real-time based on visitor behavior and profile attributes. A visual drag-and-drop editor enables non-technical users to design and redesign the website without coding.

Product Vision
Create a next-generation web experience that combines:

Intelligent visitor identification (anonymous + authenticated)
Enterprise data integration (BigQuery customer profiles)
AI-powered content generation (OpenAI)
Visual design flexibility (drag-and-drop editor)
Behavioral intelligence (navigation tracking and personalization)

8. Visitor Identification Engine
Purpose: Seamlessly switch between anonymous and authenticated states

Logic Flow:

1. Visitor arrives
2. Check for existing session cookie
   - If exists → Load visitor profile (anonymous or authenticated)
   - If new → Create anonymous visitor ID
3. Check authentication status
   - If logged in → Query BigQuery for profile data
   - If anonymous → Use behavioral data only
4. Determine visitor segment based on available data
5. Trigger content personalization
State Management:

Real-time state updates via React context
Persistent state across page refreshes
Automatic re-personalization on login/logout
9. Content Segmentation System
Purpose: Organize visitors into segments for targeted content delivery

Segment Definition:

Rule-based criteria (e.g., industry = "healthcare")
Behavioral patterns (e.g., visited pricing page 3+ times)
BigQuery profile attributes (e.g., customer_tier = "enterprise")
Combined multi-condition rules
Segment Types:

Profile-based: Derived from BigQuery data
Behavioral: Based on navigation patterns
Hybrid: Combination of profile + behavior
Default: Fallback for unmatched visitors
Segment Priority:

Authenticated users → BigQuery profile segments
Anonymous returning visitors → Behavioral segments
New anonymous visitors → Default segment

Client-side caching of content variants
Service worker for offline capability (future phase)
User Experience:

Seamless content transitions

Data Flow Examples
Scenario 1: New Anonymous Visitor
1. Visitor lands on website
2. FingerprintJS generates unique ID → Store in PostgreSQL
3. Check segment rules → Assign to "Default" segment
4. Load page design from PostgreSQL
5. Retrieve default content from content library
6. Render page
7. Track navigation behavior → Log to PostgreSQL
Scenario 2: Returning Anonymous Visitor
1. Visitor returns (recognized by fingerprint + cookie)
2. Retrieve visitor profile from PostgreSQL
3. Analyze navigation history
4. Assign to behavioral segment (e.g., "Pricing Page Visitors")
5. Load personalized content for that segment
6. Render page with targeted messaging
7. Continue tracking behavior
Scenario 3: Authenticated User
1. User logs in
2. Create authenticated session
3. Query BigQuery with user email/ID
4. Retrieve customer profile (industry, tier, purchase history)
5. Determine segment from BigQuery data (e.g., "Enterprise Healthcare")
6. Generate AI content personalized to profile:
   - Prompt: "Create headline for enterprise healthcare customer"
   - Include relevant case studies and features
7. Render highly personalized page
8. Track behavior + update BigQuery (future phase)

API Endpoints (Express.js)
Visitor Management

Authentication

POST /api/auth/logout - End session

Content
GET /api/content/:segment - Retrieve content for segment
POST /api/content/generate - AI content generation
GET /api/content/library - Browse content library
BigQuery
GET /api/bigquery/profile/:userId - Fetch customer profile

Page Design
GET /api/design/current - Load published page design
POST /api/design/save - Save page design
POST /api/design/publish - Publish design to production
Segmentation
GET /api/segments - List all segments
POST /api/segments - Create new segment
GET /api/segments/:visitorId/match - Determine visitor segment
